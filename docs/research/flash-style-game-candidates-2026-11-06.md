# 플래시 게임 감각의 미니게임 후보

확인일: 2026-11-06. 앞선 기억력·반응속도 후보는 사용자가 원하는 깊이에 미치지 못했다. 이번 기준은 **조작을 익히고, 상황에 맞춰 선택하고, 한 판 안에서 강해져 스테이지를 끝내는 게임**이다. 아래는 원작 이식이 아니라 제작사 자료에서 구조를 참고한 독자 게임 제안이다. 책상·카페 등 이름과 소재는 플레이를 설명하기 위한 선택 가능한 예시이며 채택안이 아니다. 시간·수치·화면 구성은 모두 Breakground용 설계 가정이며 플레이로 검증하지 않았다.

## 먼저 추천하는 방향

**첫 후보는 건설·강화가 있는 웨이브 디펜스**다. 4~6분짜리 스테이지에 건설·전투·강화·마지막 웨이브를 담는 것을 목표로 한다. 모바일에서도 정밀한 동시 입력 없이 전략을 경험하게 만들 수 있고, 작은 분량으로도 배치와 투자 선택의 차이가 드러난다는 판단이다. **경영 취향이면 주문 처리·설비 개선을 결합한 타이쿤**, 액션 취향이면 **짧은 방 단위 플랫폼 액션이나 전투 액션**이 더 잘 맞는다.

| 독자 게임 후보 | 한 판에서 실제로 하는 행동 | 반복할 이유·숙련 요소 | 첫 체험 범위와 시간 목표 |
| --- | --- | --- | --- |
| **책상 디펜스** | 책상 위 통로를 따라오는 종이 벌레를 막는다. 제한된 돈으로 연필 발사대·풀칠 감속기를 놓고, 빠른 적이 오면 초입 감속에 투자할지 출구 화력을 높일지 고른다. 처치 보상을 재투자하고 마지막 대형 벌레를 막는다 | 위치, 사거리 겹침, 화력/감속 예산 배분, 직접 누르는 비상 스킬의 타이밍. 두 번째 판에는 다른 배치를 시도한다 | 고정 길 1개·건설 자리 6개·방어 시설 2종·적 3종·5웨이브·강화 1단계·스킬 1개. **4~6분** |
| **점심 카페 러시** | 주문표를 받고 커피를 내리는 동안 다음 손님의 샌드위치를 조립한다. 기계가 끝나는 순서를 보고 대기 손님과 완성품을 연결한다. 전반부 수익으로 빠른 커피 머신 또는 추가 작업대를 골라 후반부 혼잡을 푼다 | 주문 우선순위, 병렬 작업, 실수 회복, 자신의 병목에 맞는 설비 선택. 클릭 속도보다 작업 순서가 중요하다 | 화면 1개·레시피 3개·작업 자리 2개·정해진 손님 8명·중간 설비 선택 1회·영업 결과. **3~5분** |
| **택배 대시** | 작은 캐릭터로 사무실 선반을 점프하며 소포를 회수하고 출구로 간다. 안전한 아래 길과 위험하지만 짧은 윗길 중 고르고, 이동 장애물을 보고 대시 타이밍을 잡는다. 실패하면 해당 방을 즉시 재도전한다 | 점프 거리·관성·대시 자원 관리, 지름길 발견, 같은 방을 더 매끄럽게 통과하는 손맛. 점수 숫자를 올리기 전에 이동 자체가 재미있어야 한다 | 한 화면 방 3개·좌우/점프/대시·고정 장애물 1종·왕복 장애물 1종·선택 소포. 방당 **30~90초**, 재도전 포함 **3~7분** |
| **고철 청소반** | 한 화면의 작업장에 들어가 순찰 로봇의 공격을 피하고 고철 탄을 쏜다. 방을 정리하면 관통탄 또는 산탄 중 하나를 골라 다음 방으로 간다. 마지막 방은 예고선을 보고 큰 공격을 피하는 적과 싸운다 | 위치 선정, 발사 방향, 적 공격의 예고 읽기, 무기 선택에 따른 거리 조절. 맞지 않고 가까이 접근할수록 전투가 빨리 끝난다 | 단층/낮은 발판 방 3개·적 2종·엘리트 1종·좌우/점프/방향 고정 사격·방 사이 강화 선택. 전체 **3~6분** |

네 게임 모두 소리 없이 공격 예고·제조 완료·피격·종료를 이해할 수 있게 설계한다. 점수판은 결산이고, 본체는 위 표의 행동과 선택이다. 1판의 업그레이드는 다음 판에 초기화하는 제안이므로 반복 재화·영구 능력치가 없어도 한 판 안에 성장감을 줄 수 있다. 여러 게임을 한꺼번에 만들 필요는 없다.

## 원작에서 확인한 구조와 제안의 차이

- **Kingdom Rush:** 제작사는 타워의 강화·특화로 방어 전략을 바꾸고 특수 능력을 가진 적에 대응하는 게임으로 설명한다. 「책상 디펜스」는 그 중 배치·재투자·적 대응의 구조를 작은 한 판에 담는 제안이다. 영웅 육성이나 대규모 캠페인을 초기 범위로 가져오지 않는다. [Ironhide 공식 소개](https://www.ironhidegames.com/Games/kingdom-rush).
- **Papa's Freezeria:** Flipline은 주문·제조·혼합·토핑 작업장을 오가는 멀티태스킹, 평가와 팁, 업그레이드를 설명한다. 모바일판은 작은 화면에 맞게 조작을 다시 설계했다고 명시한다. 「점심 카페 러시」는 작업 병행과 병목 개선을 참고하되, 3개 레시피와 한 번의 설비 선택으로 제한한 독자 구상이다. 원작의 긴 해금 진행을 3분에 그대로 압축할 수 있다고 주장하지 않는다. [Flipline 공식 상세 소개](https://www.flipline.com/apps/papasfreezeriatogo/index.html).
- **N / N++:** Metanet은 N에서 이어진 관성 중심 플랫폼 액션, 장애물 회피, 정교한 속도 제어와 수작업 레벨을 설명한다. 「택배 대시」는 이처럼 조작 숙련과 레벨 배치로 깊이를 만드는 방향이다. 3개 방은 콘텐츠 양보다 이동의 느낌과 재도전 의사를 확인하는 표본이다. [Metanet 공식 프레스킷](https://nplusplus.org/presskit/sheet.php?p=nplusplus).
- **Twin Shot:** Nitrome 제작자 글은 적을 화살로 공격하고 벽에 박힌 화살을 발판으로 사용하는 구조를 설명한다. 제작자가 올린 후속작 설명은 모든 적을 없애 다음 레벨로 진행하고 강화 아이템을 얻는다고 안내한다. 「고철 청소반」은 한 화면 전투→클리어→다음 방의 리듬을 참고한다. 벽 화살 발판 같은 추가 물리 기믹까지 첫 버전에 넣지는 않는다. [Nitrome 제작자 글](https://nitrome.newgrounds.com/news/post/726071), [Twin Shot 2 제작자 설명](https://www.newgrounds.com/portal/view/505250).

## PC와 모바일에서 달라지는 것

디펜스는 자리 선택→시설 버튼 선택, 카페는 주문 선택→재료/작업 버튼 선택으로 마우스와 탭을 공통 지원할 수 있다. 모바일 카페는 모든 주문을 작게 늘어놓기보다 선택한 주문과 남은 대기를 나눠 보여준다. 미세한 드래그 정확도나 마우스 올림에만 의존하는 정보는 피한다. 이것은 제안이며 실제 360px 화면 배치 검증이 필요하다.

액션은 PC의 방향키·점프·대시/사격이 손맛의 기준이다. 휴대전화의 가상 방향키와 점프/공격 버튼은 화면을 가리고 여러 손가락을 요구한다. 모바일까지 첫날부터 같은 액션을 제공하려면 **대시와 점프를 합치거나 자동 사격하는 별도 조작안**을 먼저 시험해야 한다. 이는 난이도와 플레이 감각을 바꾸므로 PC와 모바일의 같은 점수표를 당연하게 전제하지 않는다. 모바일도 동등한 우선순위라면 디펜스·카페가 먼저라는 판단이다.

## 첫 기능은 디펜스 한 스테이지

목적은 “시설 수가 적어도 배치를 바꾸고 다시 해 보고 싶은가”를 확인하는 것이다. 첫 체험에는 고정 경로 하나와 위 표의 시설·적·웨이브만 포함한다. 시작 예산, 비용·체력·피해량, 마지막 적의 강함은 사용자가 선택할 핵심 정책이며 지금 확정하지 않는다. 구현을 맡기면 AI가 반복 코드와 시험 환경을 지원하고 사용자가 규칙을 검토할 수 있도록 한다.

플레이 흐름은 **준비 배치 → 웨이브 시작 → 전투·비상 스킬 → 보상으로 건설/강화 → 마지막 웨이브 → 성공 또는 실패 결산**이다. 예를 들어 빠른 적은 감속 시설의 가치를, 무리 지은 적은 공격 주기와 사거리 배치의 차이를 드러내야 한다. 시설 수를 늘리기 전에 두 시설이 서로 다른 선택이 되는지 확인한다.

| 구분 | 먼저 확인할 상황 |
| --- | --- |
| 정상 | 건설 시 돈 차감·시설 생성 한 번, 처치 보상 한 번, 웨이브 종료 후 다음 준비, 마지막 웨이브의 적 전멸 후 성공 |
| 실패 | 적이 출구에 도착하면 목숨 차감. 목숨 0이면 즉시 결과. 돈 부족·이미 찬 자리·최대 강화에는 행동 불가를 시각적으로 안내 |
| 경계 | 마지막 적과 마지막 목숨 소진이 같은 순간 발생할 때 우선순위, 빠른 연속 탭의 이중 구매, 적 사망 뒤 날아오던 탄의 처리, 시작 직후/웨이브 사이 일시정지 |
| 중단·복귀 | 포커스 상실 뒤 입력이 눌린 채 남지 않는지, 재개 때 적·제조 시간이 한꺼번에 지나가지 않는지 확인. 멈춤과 재개 기준은 게임 선택 시 합의 |
| 저장 | 성공·실패 중 무엇을 완료한 GamePlay로 셀지 정한다. 결과 저장 실패 시 재시도 안내와 중복 저장 방지 계약은 별도 설계 |

## 짧게 끝내기와 이어하기의 선택

현재 `docs/decisions.md`는 **브라우저에서 상태 처리·새로고침 시 초기화·서버는 목록과 결과만 저장**한다. 이 보고서는 그 정책을 변경하지 않는다. 우선은 한 판 3~6분, 짧은 준비 구간과 명시적 일시정지로 대응하는 제안이다. 같은 페이지의 일시정지·재개는 재방문 이어하기와 다르며, 새로고침 뒤 복구를 약속하지 않는다.

지속 경영·스테이지 해금·재방문 성장을 원한다면 새로고침 초기화 정책과 저장 범위를 별도로 논의해야 한다. 공개 랭킹도 클라이언트 계산 점수를 서버에 저장하는 것만으로 진짜 기록을 보장하지 않는다. 먼저 스테이지의 클리어·재도전 재미를 확인하는 제안이며, 기존 정책·스키마는 수정하지 않았다.

## 아직 확인하지 않은 부분

공식 제작사·제작자 설명을 읽었으며 원작 실행, 독자 프로토타입, 실제 모바일 조작, 재미·시간 측정은 하지 않았다. Nitrome 본 사이트는 리다이렉트 오류로 읽지 못해 제작자의 Newgrounds 글을 확인했다. 위 수치는 구현 견적이나 완료 약속이 아니라 첫 실험의 범위다. 원작의 캐릭터·맵·자산·코드를 가져오지 않고 Breakground의 규칙과 화면으로 만든다.
