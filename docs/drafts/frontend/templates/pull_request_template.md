## Summary

해결하는 사용자 문제와 변경 후 동작을 짧게 적는다.

```text
사용자 행동 → 요청/상태 변경 → 보이는 결과
```

관련 기능 이슈: 실제 제목·링크. 기본 브랜치 대상 기능 PR이면 실제 번호로 Closes 관계를 추가한다. 일부 기능만 구현한 PR에서 부모 명세를 닫지 않는다.

## Evidence

- **Before:** 기존 화면/재현 결과/실제 실패 검증
  **After:** 변경 화면/실제 통과 검증

- 정상·실패·경계 검증: 실행한 명령/절차와 결과
- 실제 브라우저/서버 연결: 확인한 내용과 기기 기준
- 미실행·미확인: 확인하지 못한 범위

Before 실패를 실행하지 않았다면 기존 미지원 상태 또는 미실행이라고 적는다. 테스트/화면 증거를 만들어내지 않는다. 실제 문제가 없는 문서 PR에 가짜 실패 테스트를 요구하지 않는다.

## Merge Danger

**Door:** one-way 또는 two-way — 이 변경을 되돌릴 수 있는가?

**Blast Radius:** 영향을 받는 가장 작은 영역

서버 정책·스키마·쿠키/Origin·다른 방·모바일 화면에 영향이 있으면 구체적으로 적는다. 해당하지 않으면 간결하게 유지한다.
