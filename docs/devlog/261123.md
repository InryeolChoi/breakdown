# 2026-11-23

## 목표

보안 점검에서 높음으로 분류한 항목 중 공개 API 빈도 제한과 AWS root 사용을 처리한다.

## 진행 요약

11월 22일 세션 종료 직후 자정을 넘겨 이어서 작업했다. 상세 기록은 [261122.md의 "2026-11-23 00시" 절](261122.md)에 있다.

- 새 익명 사용자 발급(IP당 분당 20), WebSocket 연결(IP당 분당 60), 방 동시 연결(200), 메시지(사용자당 10초에 5), 신고(사용자당 10분에 10)에 메모리 토큰 버킷 한도를 적용했다. 유효한 쿠키의 재방문은 발급 한도에 세지 않는다. 메시지 한도 초과는 429 안내만 보내고 연결을 유지한다.
- 테스트 108개가 통과했다. 스냅샷 `breakground-before-rate-limit-20261123`을 만든 뒤 00:06에 운영 백엔드만 교체했다. 외부 IP는 한도 초과로 429, 같은 시각 서버 IP는 401을 받아 실제 클라이언트 IP별로 계산됨을 확인했다.
- IAM 사용자 `breakground-operator`를 만들고 서울 Lightsail 운영과 자기 비밀번호·MFA 관리만 허용했다. 사용자가 MFA를 등록하고 `aws login`으로 전환했다. 서버 조회·SSH 인증서·스냅샷 권한은 허용, IAM 조회와 다른 리전은 거부됨을 확인했다.

## 질문과 답변

- MFA는 어디서 등록하나: root 콘솔의 IAM → 사용자 → 보안 자격 증명에서 "MFA 디바이스 할당"으로 등록했다. 인증 앱으로 QR을 스캔하고 연속된 코드 두 개를 입력한다.
- `aws login`의 리전: `ap-northeast-2`. 운영자 정책이 서울 리전만 허용한다.
- IAM 로그인 화면의 Account ID: 계정의 12자리 숫자 ID를 입력한다.

## 확인하지 못한 것

- 운영의 메시지·신고·발급 한도는 실제 데이터를 만들지 않기 위해 시험하지 않았다. 평일 방 운영 중 메시지를 빠르게 6개 이상 보내 6번째에 안내가 뜨고 연결이 유지되는지 확인한다.
- `aws login` 재인증 후 AWS MCP 세션이 만료되면 `/mcp`로 다시 연결해야 한다.
