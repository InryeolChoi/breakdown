# 2026-11-05 — 공간과 UI 표현의 불일치

## 사용자 피드백

사용자는 입장·채팅 UI가 너무 떠 있는 느낌이라고 했다. 현재 공간형 디자인을 유지할지 담타 사이트처럼 레트로하게 할지 고민하며 UI 스킬을 더 설치해야 하는지도 물었다. 앞선 UI 배치는 승인하지 않은 상태다. 담타 사이트의 현재 화면을 이번에 확인한 것은 아니므로 구체 디자인을 알고 있다고 가정하지 않는다.

## 설명과 추천

이미 frontend-design, Web Interface Guidelines, Vercel React Best Practices가 설치되어 있다. 현재 문제를 추가 스킬 부재로 단정하지 않는다. 사실적인 공간과 화면에 고정된 평면 폼이 시각적으로 어울리지 않는 점이 디자인 문제라는 판단이다. UI를 작게 하거나 그림자만 바꾸는 것으로 끝내기보다 공간 표현과 인터페이스 표현의 관계를 먼저 비교해야 한다.

카페라는 장소·분위기와 사실적인 3D 표현은 별개다. '카페 분위기 + 레트로 인터페이스'도 검토할 수 있으며, 추천은 추가 설치 없이 같은 입장·채팅 기능으로 표현 차이가 분명한 소규모 시안을 비교하는 것이다. 기존 공간 기준은 유지하되 실제 구현 방식을 확정한 것은 아니며, 레트로 전환·픽셀아트·자유 이동도 사용자 결정 전이다. 이번에는 새 스킬 설치·이미지 생성·프런트 구현·Docker 시작·GitHub 변경을 하지 않았다.

## 직접 사용할 수 있는 두 화면 요청

이후 사용자는 두 웹사이트를 실제로 비교하고 서버에 연결해 써보자고 요청했다. 앞선 디자인만 검토하던 범위를 넘어 로컬 비교용 프런트 구현과 연동을 진행했다. 기존 승인 위치인 frontend에 Next.js·TypeScript 앱을 만들고 두 화면이 같은 입장·채팅·신고 기능을 공유하도록 했다. 추가 스킬이나 외부 계정은 연결하지 않았다.

초기 AI 해석은 공간형 대 픽셀풍 레트로였으나, 사용자는 첨부 화면으로 '단순하고 깔끔한 배경 대 건물 안에 들어간 느낌'이라고 정정했다. 픽셀 배경 실험을 현재 비교안에서 제외하고 /minimal은 단색 배경·넓은 여백·프레임 없는 UI로 바꿨다. /spatial은 실내 사진과 탁자 위 단말기 UI를 유지한다. /retro는 기존 링크의 혼란을 줄이기 위해 /minimal로 이동시킨다. 새 비교 기준이나 미니멀형을 최종 디자인으로 자동 확정하지 않는다.

## 실제 연동과 검증

- 사용자 요청에 따라 make로 PostgreSQL을 시작하고 기존 Spring 앱을 loopback:8080에서 실행했다. Flyway는 기존 V10까지 적용된 상태이며 DB 정책이나 마이그레이션은 변경하지 않았다.
- 프런트는 127.0.0.1:3000에서 실행한다. 비교 시작 화면은 /, 미니멀은 /minimal, 공간형은 /spatial이다.
- 로컬 Node 게이트웨이가 HTTP /api와 WebSocket /ws/rooms를 Spring으로 중계한다. Host·Origin을 함께 유지하며 쿠키는 브라우저 HttpOnly로 관리한다. Spring의 출처 허용을 wildcard로 바꾸지 않았다. 운영 배포 구조로 확정한 선택은 아니다.
- 기본은 예시 자동 답변이 있는 체험 모드다. 실제 모드에서는 현재 열린 기존 방에 입장하고 서버가 수신·전달한 메시지만 표시한다. 이번 실행 시 야근메뉴방이 열려 있어 별도 테스트 방을 만들지 않았다.
- 프로토콜 자동 검사 4개가 통과했다. 별도로 활성화한 실제 연동 검사 1개에서 서로 다른 두 익명 사용자 쿠키, 쿠키 없는 401, 다른 Origin의 403, 같은 방 두 연결의 동일 UUID 수신, 입력 오류 400 후 연결 유지, 신고 201과 중복 409를 확인했다. 이 검사는 로컬 DB에 검증용 사용자·메시지·신고를 생성했다.
- 브라우저에서 미니멀 체험 입장·전송·자동 예시 답변, 실제 모드 야근방 입장·WebSocket 전송 후 서버 수신을 확인했다. 공간형은 체험 입장·전송과 신고 화면/결과를 확인했다. 같은 공유 기능을 사용한다.
- 360px 모바일 두 화면의 가로 넘침과 1280px 데스크톱 배치를 확인했다. 실제 3D 시선 회전·운영 시간 종료 순간·물리적 휴대전화 조작은 이번 브라우저 검사 범위가 아니다.
- 기준 공간의 UI 없는 배경을 기본 이미지 생성 도구로 제작해 frontend/public/images/cafe-spatial.png에 보관했다. 원본 승인 이미지는 유지했다. 생성 지시는 기존 공간·빛을 유지하고 모든 글자와 폼을 제거하는 것이었다.

프런트 실행·검증 방법은 frontend/README.md에 있다. 앱을 사용해 비교할 수 있도록 로컬 서버를 유지하며 GitHub 게시·커밋·배포는 하지 않는다.

최종 변경 후 타입 검사와 production build도 통과했다. 공개 경로 /, /minimal, /spatial과 /retro의 이동 경로를 빌드 결과에서 확인했다. 원래 ZIP 삭제와 .DS_Store는 변경하지 않았다. 스크린샷은 대화용 시각화 폴더의 cafe-spatial-browser.jpg와 cafe-minimal-browser.jpg에 보관했다.

## 개인적인 추천

사용자가 AI의 개인적인 추천을 물었다. AI 추천은 미니멀형을 기본으로 먼저 검토하는 것이다. 잠깐 접속해 대화하고 쉬는 행동에 여백과 작은 UI가 잘 맞으며, 현재 공간형에서 나타난 배경과 폼의 시각적 분리를 줄일 수 있다는 디자인 판단이다. 공간형의 장소성은 장점이므로 비교 후보로 유지하되 최종 채택은 사용자가 결정한다. 미니멀형을 특정 사이트의 복제로 만들거나 어두운 배경을 필수 정책으로 확정하지 않는다.

## 공간형을 실제 3D로 비교

사용자는 공간형이 카카오 같은 인상이라고 느끼며, 미니멀을 고를지 고민하고 공간형을 3D처럼 바꿀 수 있는지 물었다. 둥근 단말기·말풍선이 익숙한 메신저 인상을 만들 수 있다는 설명은 AI 해석이다. 미니멀은 유지하고 공간형을 실제 3D 도형으로 바꿔 비교했다.

Three.js로 벽·탁자·의자·셀프바·커피 머신·정수기·간식 상자를 구성했다. 자리는 고정하고 제한된 범위에서 드래그·방향키·왼쪽/정면/오른쪽 버튼으로 시선만 돌린다. 처음에는 대화창을 접어두며 입장·대화 열기를 누르면 시선 조작이 멈춘다. 말풍선 배경·단말기 테두리도 줄였다. 자동 움직임·자유 이동·아바타는 없다.

렌더러는 공간형에서만 동적으로 불러오고 변화가 있을 때 그린다. 화면을 떠나면 도형·재질·텍스처·렌더러와 이벤트를 정리한다. WebGL 미지원/컨텍스트 손실에는 정지 배경 안내를 표시한다. 이 fallback 경로나 실제 모바일 GPU 성능까지 검증한 것은 아니다.

브라우저에서 3D 렌더링, 방향 버튼·드래그 시점 변화, 정면 복귀, 대화창 전환·체험 전송을 확인했다. 360px에서 canvas 표시·가로 넘침 없음·fallback 비활성 상태를 확인했고 콘솔 오류가 없었다. 타입 검사·계약 검사 4개·빌드도 통과했다. 서버 계약과 DB를 바꾸지 않아 앞서 통과한 실제 연동 검사를 반복하지 않았다. cafe-3d-browser.jpg를 대화용 시각화 폴더에 보관했다.

기본 도형·단순 재질의 공간감/조작감 초안으로, 승인 이미지의 재질·조명 품질을 재현했다고 보지 않는다. 미니멀 또는 3D의 최종 선택은 아직 받지 않았다.
