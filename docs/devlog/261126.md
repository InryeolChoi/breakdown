## 로컬 통합 미리보기 재개

사용자가 현재 구현 상태를 실제 로컬 서버에서 확인하자고 요청했다. 시작 브랜치는 BG-05 `07f2814`였다. 권한을 허용해 `make`를 다시 실행한 뒤 PostgreSQL 17.11과 Spring을 시작했다. Flyway V1~V10 검증이 통과했다. 기존 로컬 서버(3000)에서 오전 11시 55분 KST에 `/api/rooms`가 빈 배열을 반환했다. 당시 점심메뉴방은 11시 30분에 닫혔고 다음 방은 16시에 열린다.

BG-05의 프런트에 BG-04 `6b5553b`의 프런트 변경을 임시 디렉터리에서 적용했다. 통합 미리보기는 13000, 전용 Spring은 18080을 사용한다. 별도 PostgreSQL DB에 `로컬 검증방`을 추가해 운영 시간과 상관없이 익명 입장·채팅·신고를 확인할 수 있게 했다. Spring 테스트는 별도 테스트 DB에서 108개 통과했다. Node는 계약 4개와 실제 쿠키·WebSocket·신고 연동 1개가 통과했다. 심화 부하 검사는 실행하지 않았다. 통합 프런트 타입 검사도 통과했다.

BG-05 PR #25는 Draft다. 현재 커밋의 PR CI에서 Spring·프런트·브라우저 검사는 통과했다. 백엔드 이미지 검사는 Gradle 플러그인 의존성을 받는 단계에서 실패해 필수 CI가 실패 상태다. 같은 커밋의 push CI는 성공했다.

BG-05 작업 브랜치의 Chromium 부분 검사에서 8개 중 7개가 통과했다. 360px 모바일 에뮬레이션에서 배달 두 번 뒤 세 번째 발사가 집계되기 전에 게임 오버가 발생했다. 데스크톱에서는 5통 완료를 확인했다. 통합 미리보기에서도 기존 모바일 검사를 다시 실행했다.

통합 Chromium 검사는 14개 중 13개 통과했다. 데스크톱과 360px에서 카페 탐색·방 목록 빈 상태·채팅 초안 보존·신고 실패 후 재시도·첫 배달과 게임 오버 후 재시작을 확인했다. 데스크톱의 5통 완료는 통과했고, 모바일의 두 번째 실행에서는 3통 뒤 네 번째 발사가 집계되지 않아 5통 완료에 실패했다. 첫 실패와 두 번째 실패 모두 실제 휴대전화가 아닌 Chromium 에뮬레이션에서 관찰했다. 원인은 아직 확정하지 않았다. 통합 미리보기와 기존 로컬 서버를 실행 상태로 두었다.

### 통합 서버 재기동과 브라우저 재검증

격리 PostgreSQL을 새로 올리고 로컬 검증방을 추가했다. Spring과 Next.js를 재기동해 13000번에서 카페와 채팅방 목록이 응답하는지 확인했다. Node 계약·쿠키·WebSocket·신고 연동 검사 5개는 모두 통과했다.

Chromium은 14개 중 13개가 통과했다. 데스크톱 5통 완료와 두 화면 크기의 게임 오버 후 재시작은 통과했다. 360px 모바일 에뮬레이션에서는 세 통을 배달한 뒤 네 번째 탭에 발사 횟수가 오르지 않았고 게임 오버로 끝났다. 이전에 기록한 현상이 재현됐다. 실제 기기에서의 재현 여부와 탭이 반영되지 않은 원인은 아직 확인하지 못했다.

### 모바일 발사 누락 원인 확인

360px Chromium에서 실제 터치 이벤트를 기록하며 5통 배달을 재실행했다. 처음 네 통은 터치와 후속 클릭이 화살표에 전달돼 배달됐다. 다섯 번째는 터치 시작과 종료 모두 화살표에 전달됐지만, 후속 클릭 시 화살표 버튼 왼쪽 위치가 286px에서 192px로 옮겨 클릭이 캔버스에 전달됐다. 발사는 화살표의 클릭에서만 처리돼 4/5에 머물렀다. 자동화가 이전 좌표를 탭했다는 설명만으로는 이번 실패를 설명할 수 없다. 실제 휴대전화의 브라우저 동작은 별도 확인이 필요하다.

### 메일비행기 터치 발사 수정

화살표에서 시작한 주 터치를 추적하고 그 손가락을 뗄 때 발사한다. 화살표가 이동하는 동안에도 같은 터치를 받을 수 있도록 포인터 캡처를 사용한다. 시작 위치에서 12 CSS 픽셀을 넘겨 움직이거나 브라우저가 터치를 취소하면 발사하지 않는다. 터치 뒤 만들어지는 클릭은 발사에 다시 사용하지 않고 마우스와 키보드 동작은 기존 경로를 사용한다.

화살표를 이동시키고 후속 클릭을 막은 재현 검사는 수정 전에 발사 횟수가 오르지 않아 실패했다. 수정 후 빌드·타입 검사와 Chromium 데스크톱·모바일 16개가 통과했다. 모바일 5통 완료를 두 번 추가 실행했고 둘 다 통과했다. 실제 휴대전화에서는 아직 확인하지 않았다.

### 메일비행기 조준과 앉은 시점 시안

배달이 자동 명중하던 흐름에 조준 타이밍을 추가했다. 바늘이 가운데 구간에 왔을 때 던지면 명중하고 중심에 가까울수록 점수가 높다. 발사한 메일이 늘수록 적중 구간이 좁아진다. 빗나가면 횟수만 소모하므로 다섯 번 발사한 결과에 실제 배달 수를 표시한다.

카메라를 책상 뒤 1.48m로 낮추고 비행기 크기와 천장 밝기를 조정했다. 가까운 책상·모니터와 뒤쪽 업무 공간의 깊이를 확인했다. 통로의 별도 의자를 제거하고 앉는 동료가 책상 열에 있는 의자로 가서 착석한 뒤 통로로 복귀하도록 바꿨다. 인물 모델은 기존 모델을 사용했다.

프로덕션 빌드와 타입 검사가 통과했다. 최종 Chromium 전체 검사 18개가 통과했다. 실제 터치 발사와 키보드 조작은 개별 검사에서 확인했고, 5통 완료 검사는 조준이 맞는 프레임에 버튼을 활성화해 결과까지 확인했다.

### 메일비행기 당겨서 발사

화살표에서 마우스나 손가락을 누르고 아래로 당긴 뒤 놓으면 발사한다. 힘 게이지의 흰 눈금은 현재 동료까지의 거리에 맞는 힘이다. 조준과 힘이 모두 맞을수록 점수가 높다. 카메라 높이는 1.48m에서 1.69m로 올렸다. 키보드 Enter는 적정 힘으로 발사한다.

마우스를 60px 당겼을 때 힘 게이지 60%와 놓을 때 한 번 발사를 확인했다. 점수 검사 두 개와 빌드·타입 검사, 데스크톱·모바일 Chromium 전체 18개가 통과했다. 실제 휴대전화는 아직 확인하지 않았다.

### 당긴 채 좌우로 조준

아래로 당기는 거리는 힘, 좌우 이동은 조준점에 반영한다. 놓는 시점의 방향을 비행이 끝날 때까지 유지한다. 거리별 적정 힘과 좌우 조준 오차로 명중 여부와 점수를 정한다. 키보드는 기존 타이밍 조준을 사용한다.

프로덕션 빌드·타입 검사와 점수 검사 2개가 통과했다. 통합 브라우저 검사에서는 기존 흐름과 모바일 새 조작을 포함한 17개가 통과했다. 데스크톱 조준 검사에서 측정과 입력 사이 대기를 줄인 뒤, 새 조준 검사를 데스크톱과 모바일에서 각각 다시 실행해 통과했다. 실제 운영 SSH와 HTTPS 요청은 시간 초과했고 AWS CLI 세션은 만료됐다.
