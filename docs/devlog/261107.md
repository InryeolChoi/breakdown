# 2026-11-07 개발 기록

## 목적과 시작 상태

종이비행기 시제품과 채팅 개발 환경을 다시 연결하고 조작감을 검토한다. 전날까지 메일 꺼내기·접기·조준·투척·명중/실패·5회 결과·재시작을 구현했다. 게임 결과 저장은 아직 연결하지 않았고 새 게임 후보는 조사 단계다. 오늘은 새 파일에 질문과 답변을 이어 기록한다.

## 개발 환경 재연결

make로 Docker Desktop·PostgreSQL을 시작하고 프런트 3000과 Spring 8080을 재시작했다. 종이비행기 화면을 브라우저에 열어 메일 꺼내기 대기 상태를 확인했다. 게임 코드는 변경하지 않았다.

## 첫 조작감 피드백

사용자가 직접 플레이 후 조작이 조금 불편하다고 했다. 현재는 드래그 시작점 대비 이동량으로 좌우/높이/속도를 함께 정해 조작과 결과의 관계가 직관적이지 않을 가능성이 있다. 가장 불편한 부분이 조준·드래그 방향/힘·메일마다 누르는 과정 중 무엇인지 질문했다. AI는 화면의 조준점을 직접 움직이고 힘은 고정하는 단순화 안을 제안한다. 사용자 답변 전이며 코드는 변경하지 않았다.

사용자가 조준이 어려웠다고 답했다. 드래그 이동량으로 방향/높이/속도를 묶던 조작을 화면 위치 기반 조준으로 교체했다. 마우스로 가리키고 클릭하거나 터치 조준 후 떼어 투척한다. 전진 속도는 -12로 고정하고 클릭한 월드 좌표까지의 비행시간과 중력을 이용해 초기 속도를 정한다. 조준점과 예상 궤적을 기본 표시하고 키보드는 화면 좌표의 조준점을 이동한다. 표적을 자동 추적하지 않으며 난이도 개선 체감은 미확인이다. 타입 검사 통과. 브라우저에서 메일 접기·조준점/궤적·화면 클릭 투척·실패 후 다음 메일·키보드 조준을 확인했다. 이번 변경으로 명중률 향상이나 실제 모바일 터치 검증까지 주장하지 않는다. 캡처: plane-direct-aim.jpg.

## 추가 게임 네 개

사용자 요청으로 의자 컬링·서류 도미노·고무줄 당구·골프 솔리테어를 시제품으로 구현했다. 채팅 상단 게임 링크로 들어가는 /games 목록에 종이비행기까지 모았다. 새 물리 게임은 2D 경기판으로 비교한다. 의자는 5회 동안 멈춘 위치의 점수를 합산하고, 도미노는 배치 3개에 각각 3회 기회를 주며, 당구는 3번의 발사에서 밀어낸 메모를 센다. 골프는 15장과 보충 덱 18장으로 줄였고 A와 K를 연결하지 않는다. 규칙과 점수는 체험용이며 플레이 상태는 브라우저 메모리에 있다.

타입 검사·프로덕션 빌드 통과. 물리 계산을 직접 실행해 의자 득점, 도미노 세 배치의 성공과 약한 힘으로 실패, 당구 메모 제거를 확인했다. 브라우저에서 의자 97점과 다음 시도/초기화, 도미노 다음 배치, 당구 방향키와 스페이스로 100점, 골프 오답·카드 제거·보충 덱 감소를 확인했다. 360px에서 골프·의자 화면의 가로 넘침 없음과 의자 포인터 조준을 확인했다. 실기기 터치와 밸런스는 검토 전이다.

## 운영 시뮬레이션과 카드 퍼즐

사용자 요청으로 점심 카페 러시와 퇴근 정리를 게임 목록에 추가했다. 카페는 손님 8명의 주문과 14초 대기 시간, 커피 3초·샌드위치 5초의 병렬 준비, 제공 매출과 빠른 제공 팁으로 구성한다. 카드 퍼즐은 고정된 업무 카드 12장을 서류함 세 개에 배치해 같은 종류 세 장씩 제거한다. 한 판의 규칙과 수치는 시제품 기준이다.

카페 로직에서 전원 제공과 전원 이탈, 조리 완료 전 제공 거절, 일시정지 시 시간 고정을 확인했다. 브라우저에서는 동시 준비, 첫 주문 매출 3,500원과 일시정지를 확인했다. 카드판은 함이 꽉 찬 실패, 재시작, 12장 전부 제거를 확인했다. 두 게임 모두 360px 화면에서 가로 넘침이 없었다. 실제 기기 터치와 난이도는 검토 전이다.
