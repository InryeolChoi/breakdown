처음에는 이렇게 생각했다.

- DB
- domain (DB의 테이블을 클래스로 변환)
- repository (DB와의 연결통로)
- service (로직 처리)
    - filter (로그인 시 필요)
- dto (클래스를 프론트로 보내기 위한 처리)
- controller (프론트와의 연결통로)
- 프론트

다시 정리한 내용:
- 위 목록은 구현 순서와 각 클래스의 역할이 섞여 있었다.
- domain은 테이블 매핑뿐 아니라 서비스의 개념과 규칙을 표현한다.
- repository는 저장과 조회를 담당하고, service는 사용 사례를 처리하며 트랜잭션 경계를 정한다.
- filter는 service 아래가 아니라 HTTP 요청이 controller에 도달하기 전후에 공통 처리를 하는 위치다. 로그인에만 쓰는 것도 아니다.
- DTO는 변환 처리 자체가 아니라 요청과 응답에 필요한 데이터를 담는 객체다.

SQL을 migration 파일로 남기면 Flyway가 버전 순서대로 실행하고 적용 이력을 기록한다.
로컬에서 적용했다고 AWS에 바로 전파되는 건 아니다. 해당 migration이 포함된 앱을 배포하고 실행하면 AWS DB에도 적용된다.
