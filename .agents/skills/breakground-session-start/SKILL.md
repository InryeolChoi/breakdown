# Breakground 세션 시작

사용자가 작업 재개 의사를 표현하면, 구현이나 답변에 앞서 이 흐름을 적용한다.

1. 프로젝트 루트의 `AGENTS.md`, `CLAUDE.md`, `docs/devlog/NEXT.md`를 읽어 현재 목표와 이어 할 일을 확인한다.
2. 프로젝트 루트에서 `make`를 실행해 Docker Desktop과 PostgreSQL 개발 컨테이너를 시작한다. 실패하면 원인을 확인하고, 시작에 필요한 수정은 사용자가 직접 작성할 수 있도록 먼저 설명과 힌트를 제공한다.
3. 시스템의 현재 날짜를 `YYMMDD` 형식으로 구한다. `docs/devlog/<YYMMDD>.md`가 없으면 제목, 목적, 작업 시작 상태를 포함해 새 파일을 만든다. 이미 있으면 그 파일을 이어 쓴다.
4. 학습에 의미 있는 사용자의 질문과 그에 대한 설명·결정·검증 결과를 해당 날짜 devlog에 수시로 추가한다. 나중에 블로그 글로 다듬을 수 있게 질문, 답변, 선택 이유를 연결해 쓴다. 단순 인사, 진행 신호, 반복되는 상태 출력은 기록하지 않는다.

이 워크플로는 개발 환경 준비와 기록을 위한 것이다. Spring 기능 구현은 사용자가 먼저 작성한다. 코드 변경 전에는 변경 목적과 영향 범위를 설명하고, 코드 작성 요청이 없으면 힌트와 리뷰를 우선한다.
